# 종합프로젝트 평가표 — 포트폴리오·기술문서 작성 기준

## 0. 평가 방식

| 항목 | 기준 |
|---|---|
| 평가자 | 주강사 1인, 멘토 1인, 외부 심사위원 1인의 평가값 평균 |
| 평가 범위 | 포트폴리오·기술문서에 기재된 내용 및 증빙자료. 코드·성능·사용자 검증 결과의 별도 재현·사실 확인 없음 |
| 등급 판정 | 항목별 체크리스트 5개 기준: 5개 우수 / 4개 양호 / 3개 보통 / 2개 이하 미흡 |

> 문서에 기재되지 않은 구현·검증 내용은 평가에 반영되지 않음

| 평가 항목 | 가중치 |
|---|---|
| ① 문제·요구사항 및 산출물 정리 | 20% |
| ② 기술 선택 근거 및 설계 논리 | 10% |
| ② 핵심기술 체크리스트 | 30% |
| ③ 코드 품질 및 형상관리 | 20% |
| ④ 결과물의 실용성·활용 가능성 | 20% |

※ 아래 예시 표는 가상 프로젝트 「공공데이터·뉴스 기반 상권 분석 및 폐업 위험 예측 대시보드」 기준. 형식·작성 수준 참고용

## ① 문제·요구사항 및 산출물 정리 (20%)

### 작성 사항

| 구분 | 작성 내용 |
|---|---|
| 프로젝트 개요 | 3~4문장 문단. 문제 상황(흩어진 정보·판단의 어려움) → 해결 목표 → 수행 범위 순 |
| 특장점 | 프로젝트 특장점 3개 내외, 특장점별 근거 |
| 기존 방식 대비 차별성 | 업무 구분별 기존 방식과 본 산출물 비교. 기존 방식은 현재 업무 방식(수작업, 정기 보고서 등)으로 구체화 |

### 예시 — 특장점

| 특장점 | 내용 |
|---|---|
| 다원 데이터 결합으로 분석 신뢰성 확보 | 공공 Open API 수치 지표와 뉴스 크롤링 이슈를 결합, 단일 출처 의존 탈피 |
| 근거 기반 예측과 해석 제공 | 폐업 위험도 예측과 주요 영향 변수(유동인구, 경쟁 점포 수 등) 동시 제시 |
| 데이터 분석 전 주기 수행 | 수집 → 정제 → EDA·통계 검정 → 예측 모델링 → 시각화 → RAG Q&A 연결 |

### 예시 — 기존 방식 대비 차별성

| 구분 | 기존 방식 | 본 산출물 |
|---|---|---|
| 데이터 수집 | 사이트별 파일 다운로드 후 수작업 취합 | Open API·크롤링 자동 수집 후 정제·저장 |
| 분석 범위 | 단일 통계표 중심 기술통계 | EDA·상관분석·가설검정으로 지역 간 차이 검증 |
| 미래 예측 | 과거 실적 요약 | 회귀·분류 모델로 매출 추이·폐업 위험도 예측 |
| 정보 갱신 | 연 단위 보고서 발간 시 반영 | 파이프라인 재실행으로 최신 데이터 반영 |
| 정책 정보 활용 | 담당자가 정책 문서 직접 검색 | RAG 검색, 출처 포함 답변 |
| 결과 공유 | 정적 PDF·엑셀 보고서 | 인터랙티브 대시보드, 지역·업종 필터 |

### 평가 체크리스트

- [ ] 프로젝트 목표 및 해결 문제 제시
- [ ] 대상 사용자 및 핵심 요구사항·기능 목록 제시
- [ ] 프로젝트 특화성 및 기존 솔루션 대비 차별성 제시
- [ ] 핵심 사용자 흐름(User Flow) 제시
- [ ] 요구사항별 구현 여부 및 최종 산출물 주요 구현 결과 제시

## ② 기술 선택 근거 및 설계 논리 (10% + 핵심기술 체크리스트 30%)

### 작성 사항 — 기술 스택 표 구성

| 열 | 작성 내용 |
|---|---|
| 핵심 기술 | 적용 기술 영역 (수집, EDA·통계, ML, LLM, RAG, 대시보드 등) |
| 모델·도구·버전 | 라이브러리·모델명 및 버전 |
| 적용 기능 | 서비스 내 해당 기술 사용 기능 |
| **구현 수준** | 직접 구현 범위 및 수행 단계 |
| 선정 이유 | 요구사항·구현 목적과 연계한 선택 근거 |
| 성능 결과 | 측정 가능한 수치 목표 및 결과 |
| **증빙방법** | 성능 결과의 근거 자료 (비교표, 검수표, 이력, 화면 등) |

### 예시 — 기술 스택 표

| 핵심 기술 | 모델·도구·버전 | 적용 기능 | 구현 수준 | 선정 이유 | 성능 결과 | 증빙방법 |
|---|---|---|---|---|---|---|
| 데이터 수집 | requests, BeautifulSoup4, 공공데이터포털 API | 상권·인구 통계 수집, 뉴스 크롤링 | JSON 파싱 후 표 저장, 뉴스 제목·본문·날짜 자동 수집 | 수작업 없이 반복 수집. 수치 지표와 현장 이슈 상호 보완 | 뉴스 50,000건 이상, 결측·중복 5% 미만 | 수집 코드, 정제 전후 비교표 |
| EDA·통계 | Pandas, SciPy, Plotly | 분포·상관 분석, 지역 간 가설검정 | 결측·이상치 처리, 기술통계, t-검정 | 예측 변수 선정 근거 확보, 통계적 근거 기반 지역 특성 설명 | 가설 3개 이상 검정, p-value 해석 | EDA 리포트, 가설검정 결과표 |
| ML 예측 | scikit-learn | 폐업 위험도 분류, 매출 회귀 예측 | 모델 2개 이상 비교, 교차검증, 변수 중요도 제시 | 해석 용이 모델과 고성능 모델 비교로 설명 가능한 결과 제공 | F1 0.7 이상, MAPE 20% 이하 | 모델별 성능 비교표, 변수 중요도 그래프 |
| LLM | GPT·Gemini API (버전 기재) | 뉴스 이슈 유형 분류·요약 | 프롬프트 수정·API 호출로 분류 결과 데이터셋 추가 | 대량 텍스트의 학습 없는 정량화 | 표본 100건 정답률 80% 이상 | 분류 결과 검수표, 프롬프트 수정 이력 |
| RAG | LangChain, OpenAI 임베딩, Chroma | 지원 정책 Q&A | 문서 청킹·벡터DB 저장, 답변과 참조 문서 동시 표시 | 분석 결과와 정책 연계, 환각 억제 | 질문 50건 중 근거 일치 80% 이상 | 질문·답변·참조 문서 비교표 |
| 대시보드 | Plotly, Streamlit | 필터, 지표 카드, 위험 지도, Q&A 화면 | 현황 → 원인 → 예측 → 대응 순 화면 구성 | 사용자 직접 조건 변경 확인, Python 단일 구현 | 사용자 테스트 만족도 4.0/5.0 이상 | 실행 화면 캡처, 시연 영상 |

### 평가 체크리스트

- [ ] 주요 핵심기술 및 모델·도구·버전 제시
- [ ] 핵심기술별 적용 기능·사용 영역 제시
- [ ] 요구사항·구현 목적과 연계한 기술 선정 이유 제시
- [ ] 구조도 내 주요 구성요소 및 구성요소 간 연결관계 제시
- [ ] 기술 선택 타당성의 성능 결과·증빙자료 제시

### 핵심기술 체크리스트 (30%)

- 핵심기술 11개 항목별 구현 근거 제시 여부로 판정
- 등급: 10개 이상 우수 / 8~9개 양호 / 6~7개 보통 / 5개 이하 미흡

## ③ 코드 품질 및 형상관리 (20%)

### 작성 사항

| 구분 | 작성 내용 |
|---|---|
| 산출물 완성도 자체 평가 | ② 성능 목표 대비 최종 결과, 달성 여부. 미달 항목은 원인·개선 방향 병기 |
| 저장소 구성 | GitHub 저장소 URL, 주요 모듈·디렉터리 역할 |
| 형상관리 이력 | Issue·PR·Commit 활용 이력 및 증빙 화면(캡처) |

### 예시 — 산출물 완성도 자체 평가

| 평가 항목 | 목표 | 결과 | 달성 여부 |
|---|---|---|---|
| 뉴스 데이터 수집 건수 | 50,000건 이상 | 62,300건 | 달성 |
| 정제 후 결측·중복 비율 | 5% 미만 | 3.1% | 달성 |
| 지역 간 차이 가설검정 | 3개 이상 | 4개 (p-value 해석 포함) | 달성 |
| 폐업 위험 분류 F1-score | 0.70 이상 | 0.74 (RandomForest) | 달성 |
| 매출 예측 오차(MAPE) | 20% 이하 | 23.5% | 미달 (변수 추가 개선 중) |
| 뉴스 이슈 분류 정답률 (표본 100건) | 80% 이상 | 86% | 달성 |
| 정책 질문 근거 기반 답변률 (50건) | 80% 이상 | 82% | 달성 |
| 서비스 배포 및 외부 접속 | 배포 완료 | 배포 완료 | 달성 |

### 평가 체크리스트

- [ ] GitHub 저장소 URL 및 주요 코드 구성 제시
- [ ] 주요 모듈·디렉터리 역할 및 구성 방식 설명
- [ ] Issue 기반 작업 계획·문제 정의·진행 이력 제시
- [ ] PR 기반 코드 변경·리뷰·반영 이력 제시
- [ ] Commit 등 변경·버전관리 이력 및 증빙 화면 제시

## ④ 결과물의 실용성·활용 가능성 (20%)

### 작성 사항

| 구분 | 작성 내용 |
|---|---|
| 산업 현장 문제와 해결 방향 | 현장 문제별 프로젝트 해결 방향 1:1 대응 |
| 산업 현장 적용 방안 | 적용 대상 업무, 활용 방식, 도입 난이도(낮음·중간·높음) |
| 실제 도입 시 개선 필요 사항 | 개선 영역별 현재 수준과 필요한 개선 |
| 사용자 검증 | 사용자 테스트·인터뷰·피드백 결과, 확인된 효과·개선점, 반영 계획 |

### 예시 — 산업 현장 문제와 해결 방향

| 산업 현장 문제 | 프로젝트의 해결 방향 |
|---|---|
| 기관별로 흩어진 데이터의 수작업 취합 | Open API·크롤링 자동 수집·정제, 단일 데이터셋 통합 |
| 연 단위 보고서 중심, 최근 상권 변화 파악 지연 | 뉴스 LLM 분류·요약으로 수치 지표와 최신 동향 함께 제공 |
| 경험·직관 의존 지원 대상 선정, 사후 대응 위주 | 가설검정으로 지역 특성 검증, ML로 고위험 지역·업종 사전 예측 |
| 정책 문서 과다·잦은 변경으로 적합 정책 탐색 곤란 | RAG 기반 정책 Q&A, 출처 포함 답변 |

### 예시 — 산업 현장 적용 방안

| 적용 방안 | 내용 | 도입 난이도 |
|---|---|---|
| 지자체·지원기관 상권 모니터링 | 지역·업종별 지표와 뉴스 이슈 정기 확인, 현황 보고 활용 | 낮음 |
| 폐업 위험 기반 선제 지원 대상 선정 | 모델 제시 고위험 지역·업종 검토 후 지원 우선순위 반영 | 중간 |
| 예비 창업자 입지 상담 | 희망 지역·업종의 경쟁 현황·위험도·지원 정책 안내 | 낮음 |
| 정기 보고서 자동화 | 파이프라인 재실행으로 최신 데이터 반영, AI 변화 요약 초안 작성 | 중간 |

### 예시 — 실제 도입 시 개선 필요 사항

| 개선 영역 | 현재 수준 | 필요한 개선 |
|---|---|---|
| 데이터 범위·정밀도 | 공개 공공데이터, 행정동·분기 단위 | 카드 매출·유동인구 등 기관 보유 데이터 연계, 수집 주기 단축 |
| 예측 정확도 | F1 0.74, MAPE 23.5% (참고 지표 수준) | 변수 추가·모델 고도화, 정기 재학습, 사후 검증 체계 |
| 수집 안정성 | 수동 실행, 사이트 구조 변경 시 크롤러 수정 필요 | 수집 스케줄링, 오류 알림, 이용 약관 준수 점검 |
| 개인정보·거버넌스 | 집계·공개 데이터만 사용 | 사업체 단위 데이터 비식별화, 접근 권한 관리, 외부 AI API 전송 정책 |
| 결과 해석·활용 | 분석 담당자 직접 해석 | 비전문가용 해석 가이드, 예측 결과의 "참고 자료" 명시 원칙 |

### 평가 체크리스트

- [ ] 적용 대상 산업현장의 업무·프로세스 제시
- [ ] 실제 사용자의 구체적 활용 시나리오 제시
- [ ] 사용자 테스트·인터뷰·피드백 등 검증 결과 제시
- [ ] 검증 결과 기반 활용 효과·개선 필요사항 제시
